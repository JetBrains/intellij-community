Reports an ==, !=, is, is not, in or not in comparison that is always True or always False, because the types of its operands do not overlap.

The inspection does not report a comparison with a type that can define its own __eq__ method, for example Decimal == 0. A class that is not final can get its own __eq__ method in a subclass. The inspection ignores the subclasses of str, bytes and the number types.

The inspection reports in and not in only for a builtin tuple, list, set, frozenset or dict. Another container can define its own __contains__ method.

Example:


def f(name: str, data: bytes, count: int):
    if name == 0:  # Always False
        ...
    if data == "a":  # Always False
        ...
    if count is not None:  # Always True
        ...
    if name in (1, 2):  # Always False
        ...

As a fix, compare values of the same type, or correct the type annotation.
