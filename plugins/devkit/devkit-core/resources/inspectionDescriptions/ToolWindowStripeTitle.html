Reports a toolwindow.stripe.* key that the platform cannot read.

The inspection highlights both ends of the problem: the id attribute of the <toolWindow> extension, and the key in the resource bundle.

How a stripe title works

A tool window shows its stripe title on the stripe button. The platform builds the key from the tool window ID. It adds the prefix toolwindow.stripe. and replaces every space with an underscore. The tool window Version Control therefore needs the key toolwindow.stripe.Version_Control.

The platform reads that key from one bundle. It never searches other bundles. Two rules decide which bundle it reads:

  • The core plugin owns the module, so the platform reads messages.IdeBundle. It ignores the bundle that the descriptor declares.
  • A plugin owns the module, so the platform reads the <resource-bundle> of the descriptor that declares the <toolWindow> extension.

A content module does not inherit <resource-bundle> from the plugin.xml of its plugin. Each content module declares its own bundle. A descriptor without a declaration gets no bundle, and the platform then reads no stripe title at all.

Why the problem is easy to miss

A missing key is silent. The platform falls back to the tool window ID, and it logs nothing. The stripe looks correct in English, because the ID often reads like the title. The title stays untranslated in every language pack.

This commonly happens after a module moves out of the platform into a plugin. The key stays in messages.IdeBundle, which the platform no longer reads for that module.

How to fix it

Choose one of two changes:

  • Move the key into the bundle that the descriptor declares.
  • Declare the bundle that already holds the key. Add <resource-bundle>messages.MyBundle</resource-bundle> to the descriptor.

Before you change a declaration, check every other element in the descriptor that needs a bundle. An <actions> block, a configurable, a notification group, an inspection and an advanced setting can all use the declared bundle. Pin each one with its own bundle or resource-bundle attribute, or move its keys too.

When the inspection stays silent

  • No bundle holds the key. Then there is nothing to move. Add the key to the bundle that the descriptor declares.
  • The factory sets the title itself. ToolWindowFactory.init() can call setStripeTitle or setStripeTitleProvider. That call runs after the platform installs the bundle-derived title, so it wins, and the bundle does not matter. A call to setStripeShortTitleProvider does not count. The short title is a separate string, and the stripe title still comes from the bundle.
  • The owner of the descriptor is unclear. The inspection reports a problem only when it can prove which bundle the platform reads.
