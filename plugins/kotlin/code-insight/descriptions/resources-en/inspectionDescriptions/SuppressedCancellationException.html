Reports catch clauses and runCatching calls that could suppress a CancellationException.

Cancellation in coroutines is cooperative. A cancellation is propagated by a CancellationException. Catching it without re-throwing it, keeps the coroutine running after it was canceled.

Example:


    suspend fun load(): Data? = try {
        fetch()
    } catch (e: Exception) {
        null
    }

Call ensureActive() to re-throw the cancellation before handling the failure:


    suspend fun load(): Data? = try {
        fetch()
    } catch (e: Exception) {
        if (e is CancellationException) currentCoroutineContext().ensureActive()
        null
    }

Alternatively, catch CancellationException separately and re-throw it:


    suspend fun load(): Data? = try {
        fetch()
    } catch (e: CancellationException) {
        throw e
    } catch (e: Exception) {
        null
    }

The same applies to runCatching, which also catches CancellationException:


    suspend fun load(): Data? = runCatching { fetch() }.getOrNull()

Add an onFailure link to the chain to re-throw the cancellation:


    suspend fun load(): Data? = runCatching { fetch() }
        .onFailure { if (it is CancellationException) currentCoroutineContext().ensureActive() }
        .getOrNull()

Calling ensureActive() after the call works as well:


    suspend fun load(): Data? {
        val result = runCatching { fetch() }.getOrNull()
        currentCoroutineContext().ensureActive()
        return result
    }
