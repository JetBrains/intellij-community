Reports property getters that return a new mutable object on each access.

A property that holds a mutable object normally keeps one object. Every caller then reads and changes that same object.

A getter breaks this. It runs again on each access and returns a new object, so a caller changes an object that no other caller reads.

The inspection covers the coroutine objects Job, SupervisorJob, CompletableDeferred, CoroutineScope, MainScope, MutableStateFlow, MutableSharedFlow, Channel, Mutex and Semaphore.

It also covers a mutable collection factory such as mutableListOf or mutableMapOf.

Example:


  class Service {
      val job get() = Job()
      val items get() = mutableListOf<String>()

      fun add(value: String) {
          items.add(value) // lost: this writes to a new list
      }

      fun stop() {
          job.cancel() // no effect: this cancels a new job
      }
  }

To share one object, declare the property with an initializer:


  class Service {
      val job = Job()
      val items = mutableListOf<String>()

      fun add(value: String) {
          items.add(value)
      }

      fun stop() {
          job.cancel()
      }
  }

If you want a factory, use a function instead. A name such as newJob() shows the intent to the caller.
